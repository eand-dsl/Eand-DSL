<EN>
The etisalat Consumer App design system ships as a single npm package built from one token
source (`variables.json`, exported from the Figma DSL V1.2 library) — the same source
that generates the SwiftUI and Compose tokens, so values never drift between platforms.
</EN>

<AR>
يُطرح نظام تصميم تطبيق اتصالات للأفراد في حزمة npm واحدة مبنية من مصدر رموز واحد
(`variables.json`، المُصدَّر من مكتبة نظام التصميم في Figma بالإصدار 1.2) — وهو
المصدر نفسه الذي يولّد رموز SwiftUI وCompose، فلا تتباين القيم بين المنصّات.
</AR>

## Install

```bash
npm install @eand/react-design-system
```

<EN>
Components, design tokens, and the full **etisalat App Icons** set all come from this one
package — there is no separate icons package.

Components are inline-token-styled, so they render correctly with no CSS import. If you
want the raw `--eand-*` custom properties for your own styles, import the stylesheet
once:
</EN>

<AR>
تأتي المكوّنات والرموز التصميمية ومجموعة **اتصالات App Icons** كاملةً من هذه الحزمة
الواحدة — فلا توجد حزمة منفصلة للأيقونات.

تُنسّق المكوّنات نفسها بالرموز مباشرةً في السمة `style`، لذا تُعرض بشكل صحيح دون
الحاجة إلى استيراد أي ملف CSS. وإذا أردت الخصائص المخصّصة الخام `--eand-*`
لتنسيقاتك الخاصة، فاستورد ملف الأنماط مرّة واحدة:
</AR>

```tsx
import '@eand/react-design-system/styles.css';
```

## First screen

```tsx
import { TopBar, Section, ListRow, Button, Icon } from '@eand/react-design-system';

export function Account() {
  return (
    <>
      <TopBar
        surface="brand"
        account={{ greeting: 'Hi, Ahmed', name: '050 •••• 567' }}
        actions={[<Icon name="notification" />, <Icon name="settings" />]}
      />
      <Section title="My Plan" context="Freedom Live Plan 200">
        <ListRow label="2 GB left" value="Local Data" chevron={false} />
        <ListRow label="200 min left" value="Minutes" chevron={false} />
      </Section>
      <Button variant="primary" block>Make your own deal</Button>
    </>
  );
}
```

<EN>
`TopBar` is slot-based: `surface` picks the header card — `brand` red for the account
home, `midnight`, `white` for pushed pages, or `none` on a grey or midnight canvas —
`account` renders the greeting over a masked number, and `children` adds add-ons under
the header: a search field, `Tabs`, chips or a `Stepper`. The older `variant`,
`greeting` and `actionBar` props still compile but are deprecated aliases — reach for
`surface`, `account` and `children` instead.
</EN>

<AR>
يعتمد `TopBar` على الخانات: تحدّد `surface` بطاقة الترويسة — `brand` الحمراء
للصفحة الرئيسية للحساب، أو `midnight`، أو `white` للصفحات الفرعية، أو `none` فوق
خلفية رمادية أو كحلية — وتَعرض `account` عبارة الترحيب فوق رقم مُقنَّع، وتضيف
`children` إضافات أسفل الترويسة: حقل بحث أو `Tabs` أو كبسولات أو `Stepper`. أما
الخصائص القديمة `variant` و`greeting` و`actionBar` فما زالت تُترجَم برمجيًا، لكنها
أسماء بديلة مُهمَلة — استخدم `surface` و`account` و`children` بدلًا منها.
</AR>

## Typography

<EN>
The ramp is designed for **Suisse Int'l** (Latin) with a parallel `aed/*` ramp for
Arabic. The font is licensed — load it in your app yourself. Until it's present the
components fall back to `"Helvetica Neue", Inter, system-ui`.
</EN>

<AR>
صُمّم تدرّج الخطوط لخط **Suisse Int'l** (اللاتيني) مع مجموعة `aed/*` موازية للعربية.
الخط مرخّص — فحمّله في تطبيقك بنفسك. وإلى أن يتوفّر، تعود المكوّنات إلى
`"Helvetica Neue", Inter, system-ui`.
</AR>

## Icons

<EN>
Icons are part of the package — never generate or inline ad-hoc SVGs:
</EN>

<AR>
الأيقونات جزء من الحزمة — لا تُنشئ أبدًا رسومات SVG مرتجلة ولا تُضمّنها في الكود:
</AR>

the whole set in [Icons](/docs/foundations/icons).

<AR>

المجموع. استعرض المجموعة كاملةً في [الأيقونات](/docs/foundations/icons).
</AR>

## Figma Make

<EN>
`@eand/react-design-system` doubles as a **Figma Make kit**: register the package in Make
and it assembles etisalat screens from these exact components.

Make kits install from an npm registry, so the package has to be published — to Figma's
private org registry or to public npm. The release artifact lives at
[`eand-dsl/eand-make-kit`](https://github.com/eand-dsl/eand-make-kit), which also carries
the `MAKE_KIT_GUIDELINES.md` you paste into the kit's `guidelines/guidelines.md`. That
file isn't optional — the package alone gives Make the components, the guidelines are
what teach it how to assemble a screen.
</EN>

<AR>
تعمل حزمة `@eand/react-design-system` كذلك كـ **عُدّة Figma Make**: سجّل الحزمة في
Make لتُجمّع شاشات اتصالات من هذه المكوّنات بعينها.

تُثبَّت عُدد Make من سجلّ npm، لذا يجب نشر الحزمة — إمّا في سجلّ Figma الخاص
بالمؤسسة أو في سجلّ npm العام. ويقع أثر الإصدار في
[`eand-dsl/eand-make-kit`](https://github.com/eand-dsl/eand-make-kit)، وهو يحمل أيضًا
ملف `MAKE_KIT_GUIDELINES.md` الذي تلصقه في `guidelines/guidelines.md` الخاص بالعُدّة.
وهذا الملف ليس اختياريًا — فالحزمة وحدها تمنح Make المكوّنات، أما الإرشادات فهي التي
تُعلّمه كيف يُجمّع الشاشة.
</AR>
