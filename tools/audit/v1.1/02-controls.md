## Notes per component

### Button
Figma V1.1 set `button` (25394:85067) has **four** types — primary, secondary, tertiary (text-only), link (underlined text) — verified visually. Surface axis per type: primary → brand, inverse-brand; secondary → brand, white; tertiary/link → brand, white, midnight. States default/focus/disabled (no hover — mobile DSL). Heights sm 32 / md 40 / lg 48 match code exactly. Code drift: only primary|secondary, tone brand|inverse (2 of 4 surfaces), no focus styling. Page also carries Figma-only extras: **UAE Pass** login buttons (section 25858:54148, Language=Arabic/English) and **Floating Buttons** (section 25858:54149: FindMe, Live chat support, Satellite view) plus a fresh "butto sizes updte" section (29200:17512) — none exported in code; likely out of scope for the web package but should be logged. `anatomy/buttons.md` is already V1.1-current.

### Input Field
Page is 🟡 (in progress). The V1.1 set `input-field` (29010:3152) abandoned the V1.0 "Style=Filled/Outlined" model entirely: axes are now `type` (text, comment, dropdown, otp, picker) plus boolean state flags (default/active/filled/disabled/error) where **filled means has-a-value**, not a visual style. Code's `variant: 'outlined' | 'filled'` prop therefore maps to nothing in V1.1. Figma adds `.input-surface` + `.input-surface-inverse` atoms, `.addon` (position Left/Right), and `.input-status` (error/neutral/Success). Symbol height 82 (≈52 field + label + status rows) — code field height 52 is consistent. The page also hosts an old "(OLD) update" section (27715:734) — ignore. `anatomy/input-field.md` node 28817:43927 and the Filled/Outlined axes are stale.

### Chips
Two sets now: `Chips` (28472:2809) with state × surface (default/inverse), and a **new** `suggestion-chips` (28556:5954) with state only — both h 40. Loader atoms (`Loader <-> Icon=on/off`) exist for an in-chip loading state. Code `Chip` uses a `selected` boolean that is not a Figma axis (Figma's focus state is the closest analogue) and has no inverse surface or loader. `suggestion-chips` has no code export at all.

### FilterPill
Closest match in the section. Figma set 26151:391: State (Default/Focused/Disabled) × Color (Default/Inverse); anatomy annotations confirm h 40 fixed, hug width, radius 1200, 1px stroke, 16px chevron, single-line label — all of which code honors (Icon xs = 16). Gaps: no Color=Inverse in code, no disabled prop, and `selected` should be documented as mapping to State=Focused. `anatomy/filter-pill.md` node-ids verified live (26130:30745, 26151:392, 26151:442, 26151:3656/3664/3672).

### Checkbox
V1.1 set `checkbox` (27685:5017) is richer than code: color-scheme (default/inverse) × **radio-mode** (`radio (single selection)=yes/no` — the checkbox doubles as a round single-select) × size (sm/md) × selected × Disabled. Dimensions: **md 20×20, sm 16×16** — code renders a 24×24 native input, so even the base size drifts. `anatomy/checkbox.md` cites node 29200:17377 and three sizes (lg/md/sm) — both stale. design.md ("height: fixed (lg24 / sm20)") is also stale vs V1.1.

### Switcher
Axes match code conceptually (size, on/off, disabled) but Figma adds color-scheme=inverse. **Dimension conflict inside Figma itself:** the published variant symbols measure lg 40×24 / sm 32×20, while the page's own Sizes + Anatomy documentation frames state "Large: 56×24px", "Small: 48×20px" and place 56×24 instances. Code (56×24 / 48×20) matches the documentation, not the symbols. Needs a designer ruling before any code change. Knob 2px padding, brand-red on-track, always-white knob, no border — all match code. `anatomy/switcher.md` node 26215:7141 verified.

### Radio
Set `radio-button` (26369:775): color-scheme × small × selected × Disabled; lg 24×24 (code matches), sm 20×20 (missing in code), inverse missing in code. Page docs confirm On dot = brand red. `anatomy/radio.md` node verified; add the color-scheme axis to its variants line.

### Searchbar (incl. AISearch disposition)
Page 28114:62397 is 🔵 and contains **no published Searchbar component set** — only example `Search` frames (345×52, 16px pad) in section `Standard search` (28114:62804) across white/midnight surfaces and Default/Typing/Typed states, plus the `.Blinking Cursor prototype` symbol set (28490:6214). Trailing affordance is either mic or arrow-right-circle submit; leading icon swaps search → close-x once typing. Code Searchbar aligns on height/shape/mic but lacks the midnight surface, clear (x) affordance, and submit-arrow mode.

**AISearch: MOVED, not removed.** The old "AI Search" (V1.0 node 28189:33142, still referenced by `anatomy/ai-search.md` and design.md §AI Search) now lives on this Searchbar page as section **`AI Search component` (30635:82333)** with six state examples: Default, Focus, Typing, Dictation started (soundwave + stop circle), Transcribing (dots + stop), and stop-tapped/typed (text + send arrow). It is built as state layouts inside Section instances, not as a variant component set. Code `AISearch` is currently just `Searchbar` with a different placeholder — none of the voice states exist.

### Selectors → Pickers (disposition)

Component sets: `pickers` **31358:139406** (Property 1 = Default/Light/Glass/Inverse × Selected × Disabled, tiles 106×72) and the newer refactor `picker` **31358:141899** (color-scheme default/inverse) built from atoms `.picker-label-default/-inverse` (31358:139932 / 31358:141370), `.picker-body-default/-inverse` (31358:141371 / 31358:141380), `.surface-default` (sunken|default, 31358:141756), `.surface-inverse` (glass|midnight, 31358:141835).
